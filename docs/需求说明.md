# 需求说明（第一周初稿 v0.1）

课题负责人：任若菡。项目：南京某工业园区能耗采集与预测预警系统。唯一业务依据：学生版任务书。

## 1. 目标与范围

最终实现模块 A（数据采集与能耗核算）和模块 B（预测与异常预警）。完成后可查询区域日用电曲线、查看未来七天预测与历史异常，并给出可复现的预测/异常评估数字。只管理电力和水。不扩展碳足迹、权限、供应链、大屏、容器化或 CI/CD。

第一周交付：需求说明、接口契约、五个指定目录、前后端可访问空壳、独立算法服务空壳、建表和种子脚本、全年造数和标准答案、README 和周报。额外提供只读筛选分页预览，验证前后端与数据库连接；它不是第二周完整数据查询模块。

## 2. 业务口径

- 区域：园区 → 车间 → 产线。查询区域包含其所有后代。园区区域只是组织根节点，本任务只有六块器具，不额外虚构 10kV 总表记录，避免重复计量。
- 器具：EL-1001/2/3/4/5 和 WT-2001，共六块。EL-1001 挂产线区域 6，区域 6 属一车间 2；其余挂任务书对应车间。
- 原始值是某小时消耗量，不是累积表底，不做差分。时间用 `YYYY-MM-DD HH:mm:ss`，小时边界分钟秒均为 00。业务时区统一 Asia/Shanghai；2026 年南京全年无夏令时，每日 24 点。第一周以无偏移本地字符串持久化，跨时区外部采集接入时再统一转换。
- 电力用 kWh，水用 t。禁止将二者直接相加成总消费量。综合能耗用折标后 kgce 相加，碳排放用 kgCO₂ 相加。
- 电力：折标 0.1229，排放 0.5703；水：折标 0.0857，排放 0.344。严格使用任务书提供参数，未做外部因子替换。
- 金额不涉及。显示保留两位小数，内部求和后再舍入，不能逐项先舍入换算值再求和。
- 原始质量 1/2/3 表示上报状态，不等同于算法标准答案。缺失通过缺行表示，不能填成 0；算法应对完整小时网格识别缺失。

模拟采集的设计：每分钟回放一段已造好的小时数据，按 `(data_time, device_id)` 游标递增，数据库唯一约束防重复。缺行不制造伪值；记录本次写入数与时间范围。第一周 bootstrap 全量导入只验证数据层，不宣称已经实现定时采集。

统计待第二周实现：区域树后代包含、能源分开求和、数据质量筛选口径显式化。计划默认纳入所有已上报值，并返回质量分布与完整性计数；正常值统计可通过质量筛选请求，缺失不自动补零。手工补录唯一键冲突返回 409，明确的更正接口才允许覆盖。

## 4. 数据与异常规格

2026-01-01 至 2026-12-31，共 365×24×6=52,560 个理论点。采用任务书基础负荷、白天 ×1.6/其他 ×0.7、周末 ×0.2、指定月份 ×1.15、独立设备噪声 N(1,0.08)。无真实设备，全部是合成数据，含未来日期是模拟场景设定。

随机种子默认 42。使用 Python 标准库随机数而非任务书示例的 NumPy，业务公式一致，随机序列不要求与示例相同。同一 Python 版本与相同参数可获得字节一致 CSV。

- 缺失：完整网格中按 1% 抽取，实际删除行；truth 保留设备与时间。
- 突变：按 0.5% 抽取，随机 ×5 或 ×0.1，记录具体类型与变更前后值。
- 漂移：按 0.3% 的点数换算成完整 12 小时事件，最近整数取整。第 j 个点（j=1…12）乘 `1+0.3j/12`，从 1.025 到 1.3；下一小时回到原始基线。保留事件 ID、首末点以及每点真值。
- 漂移前后保护一个小时不注入其他异常，保证之后恢复；三种异常互斥，比例分母统一用完整网格。因点数/窗口取整，实际比例与目标有微小差异；报告两者，不伪造恰好比例。
- injected 异常继续标记上报质量 1，模拟仪表未发现的异常；truth 单独文件，训练和推理严禁读取。禁止把真值标签泄漏进特征。

## 5. 架构与技术决定

前端独立 HTTP 服务（5173），同源 `/api/` 代理至后端（8000）；后端 Controller → Service → Mapper → SQLite；算法服务（8001）独立进程。算法调用将在第三周由后端实现，第一周只提供真实 health 与未就绪状态。

第一周采用 Python 3.10+ 标准库、SQLite、原生 HTML/CSS/JS，零额外安装、无 CDN。任务书的 React/Ant Design/ECharts/Java 是建议，不是硬约束。这样保证离线环境也能运行第一周空壳；第二周若采用 React 必须先确定版本并实际安装、构建、联通测试。当前没有宣称已完成 React 构建。SQLite 使用外键、唯一约束、质量/时间索引。无数据库口令，无真实环境配置。

Swagger UI 是建议项。本期提供 OpenAPI 3.0 契约和本地离线接口调试页，可导入 Swagger Editor/Apifox；没有依赖外部 CDN 的 Swagger 页面。后续若要求嵌入 Swagger UI，需本地 vendor 资源。

## 6. 非功能与限制

所有页面处理加载/无数据/出错。API JSON 响应统一包络；未知路由 404、参数不合法 400、服务不可用 500；浏览器代理失败 502。JSON 最大 64KiB，分页最大 200。SQL 参数绑定，服务绑定本机 127.0.0.1。

本期是开发演示服务器，不用于公网生产。未实现第二至四周的修改接口、采集调度、统计和算法；这些不能作为第一周完成项。标准库随机序列跨 Python 版本不保证永久一致，验收需记录实际 Python 版本。
